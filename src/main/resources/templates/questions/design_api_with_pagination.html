Design API with Pagination

You are given the task to design an API. Your API is going to have one function, where given a long-integer company ID, it is going to return a list of Employee objects.

Here is how an Employee object is defined: 


    class Employee {
        long id;
        String firstName;
        String lastName;

        // Plus all the relevant getters and setters.
    }

Your API function is going to have access to an instance of a database proxy interface called DatabaseProxy, which contains the only following function: 


    interface DatabaseProxy {
        List<Employee> getEmployees(long companyId);
    }

So your API function is going to call the dbProxy.getEmployees() method, then return the retrieved list of employees to the caller. This is your only interface to the database. Pretty straightforward so far.

The dbProxy.getEmployees() method returns all the employees for the given company in a sorted order, sorted according to increasing employee ID. The caller of your API wants the list of employees in the same sorted order returned from the database. So there is no need for you to do any kind of additional sorting.

However, the caller of your API has one important caveat:
They can only handle so many employee objects at a given time, for each call.

Therefore, you're going to have to design an API with pagination capability. Your API is going to have to return a limited subset of the database records each time it's called. It is going to be called multiple times until all the records that the caller wants are returned to the caller.
