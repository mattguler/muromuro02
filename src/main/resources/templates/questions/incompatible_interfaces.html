Incompatible Interfaces

There is a Processor interface defined in your codebase. This interface defines a run() method which accepts two integer arguments, and returns an integer result. 


    public interface Processor {
        int run(int x, int y);
    }

There is also a Processor1 class defined, which implements the Processor interface. What exactly this implementation does is not really important for the purposes of this question. You can think of it as a blackbox. 


    public final class Processor1 implements Processor {

        @Override
        public int run(int x, int y) {
            // Some complicated implementation here.
            ...
            return someResult;
        }
    }

In the codebase, there is also a Client class defined. The Client class contains a runProcess() method definition which accepts a Processor instance as well as an x integer argument. The Client class determines the y value itself after a series of complex calculations in the runProcess() implementation, and finally calls processor.run(x, y). Once again, what exactly this implementation does is not really important for the purposes of this question. 


    public final class Client {

        // Other fields and methods of Client are defined here.
        ...

        public int runProcess(Processor processor, int x) {
            // The y value is determined here after a series of calculations.
            ...
            // And finally, call the processor and return the result.
            return processor.run(x, y);
        }
    }

You have your own MyClass which you are working on. It accepts a Client instance and a Processor instance in its constructor, which then assigns to respective member fields. MyClass also contains a runProcess() method which accepts an x argument, with which it makes a call to the client as seen below: 


    // This implementation is soon about to change.

        private final Client client;
        private final Processor processor1;

        public MyClass(Client client, Processor processor1) {
            this.client = client;
            this.processor1 = processor1;
        }

        public int runProcess(Client client, Processor processor1, int x) {
            return client.runProcess(processor1, x);

All is nice and well, until one day...

Your project requirements change.

You now have to use more processors to get the job done. You are given instances of Processor2 and Processor3. You need to use them in your MyClass along with the already existing Processor1 instance. In your runProcess() method, depending on the exact given x value, you are going to call client.runProcess()with one of the given processor instances.

However, there are a few additional twists.

First of all, the new processor classes do not implement the Processor interface. They are completely separate classes with their own method definitions: 


    public final class Processor2 {
        public int makeCalculations(int x, int y) {
            ...
        }
    }

    public final class Processor3 {
        public int execute(int x, int y) {
            ...
        }
    }

You are not allowed to make any changes to any of the class definitions of Processor1, Processor2, Processor3, Client, and the Processor interface. These classes are already used in dozens of places all over the codebase, so no changes are allowed. You can only change your own part of the codebase.

Also, because of the way everything is implemented, when the the Processor2 and Processor3 instances are called, the caller needs to make some offset adjustments to their y argument values, as following: 


    processor2.makeCalculations(x, y - 1);

    processor3.execute(x, y + 1);

One cannot call all these 3 processors with the same y value. The necessary offset adjustments need to be made, otherwise the system won't operate correctly.
