Duplicate RPCs

You are developing a client-server system. The server is designed as a key-value store. For a given key, it stores a list of given objects. The client and server communicate through Remote Procedure Calls (RPC). The service interface is defined as the following: 


    // Key-Value List storage service definition.
    public interface KVListService<K, V> {
        List<V> get(K key);
        void append(K key, V value);
        void replaceAll(K key, Iterable<V> values);
        void delete(K key);
    }

The server is implemented as the following. As you can see, at this point it is just a simple wrapper around the database. 


    // Key-Value List storage service implementation.
    public final class KVListServiceImpl<K, V>
            implements KVListService<K, V> {

        private final KVListDb<K, V> db;

        public KVListServiceImpl(KVListDb<K, V> db) {
            this.db = db;
        }

        // Returns null if no list exists for the given key.
        @Override
        public List<V> get(K key) {
            return db.get(key);
        }

        // Creates a new internal list first if none exists for the given key.
        @Override
        public void append(K key, V value) {
            db.append(key, value);
        }

        // Creates a new internal list and populates it with all the
        // elements from the given iterable into the list, for the given key.
        @Override
        public void replaceAll(K key, Iterable<V> values) {
            db.replaceAll(key, values);
        }

        // Trying to delete a non-existing key will be a no-op.
        @Override
        public void delete(K key) {
            db.delete(key);
        }
    }

And finally, your client implementation is as the following. The client accepts a serviceProxy reference to the KVListService. The Proxy takes care of making the actual RPC requests to the server. 


    public final class KVListClient<K, V> {

        private final KVListService<K, V> serviceProxy;

        public KVListClient(KVListService<K, V> serviceProxy) {
            this.serviceProxy = serviceProxy;
        }

        public List<V> get(K key) {
            return serviceProxy.get(key);
        }

        public void append(K key, V value) {
            serviceProxy.append(key, value);
        }

        public void replaceAll(K key, Iterable<V> values) {
            serviceProxy.replaceAll(key, values);
        }

        public void delete(K key) {
            serviceProxy.delete(key);
        }
    }

Once you finish implementing your client-server system and start testing it, you realize there is a serious problem...

Due to some issues in the network, and due to the way the RPC system is implemented, some of the RPC requests are being duplicated. Some copies of the RPC requests arrive multiple times to the server, which are then all processed. The processing of duplicate RPC requests are causing unpredictable results in the database storage.

Please identify and fix this issue of duplicate RPC requests.

A few additional points to mention:

  • Please feel free to make any changes to the Client and Service implementations.
  • You can make changes to the Service interface as well, however, you should not touch the Client's own method signatures, as indicated below.
  • You can assume that any changes you make to the KVListService interface definition are automatically going to be reflected on the serviceProxy implementation. The RPC system is going to take care of marshalling any new method arguments, etc.
